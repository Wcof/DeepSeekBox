# 插件装不上：「引擎版本不符」到底在说什么

> **归属说明：** 本文讲的这套 `engines.dsh` 判定逻辑，属于 **DeepSeek Harness（DSH）宿主及其适配器**，不是 PlugBox 核心层的通用规则。PlugBox 的核心层只负责「把宿主声明的兼容范围如实呈现」，真正的安装准入判断始终发生在宿主侧。如果你用的不是 DSH，本文的具体规则不适用，但「范围该写成区间而不是枚举」这条写作建议是通用的。

> 一篇写给 DeepSeek Harness 用户和插件作者的排查笔记。基于 2026-10-31 的 DSH `0.2.1-rc.5` 与插件 `qiaomu-home-dsh@0.3.1` 实测。

## 现象

在插件市场点「安装」，pnpm 装完之后被宿主拒绝并回滚：

```
qiaomu-home-dsh@0.3.1 与 DSH 0.2.1-rc.5 不兼容（要求 engines.dsh 0.2.1-rc.2 || 0.2.1-rc.3），
运行它可能导致崩溃或数据丢失。请安装与当前 DSH 兼容的插件版本。
```

注意两个细节：**包已经装进 profile 了又被撤掉**（`~/.dsh/profiles/<profile>/package.json` 里没有残留），以及报错明确写出了「要求」的范围。这说明不是网络问题，也不是包坏了，而是版本声明对不上。

## 根因：插件把兼容范围写成了「精确枚举」

插件的 `package.json` 里有一行：

```json
"engines": { "dsh": "0.2.1-rc.2 || 0.2.1-rc.3" }
```

DSH 的判定逻辑在 `@deepseek-ai/dsh-app-boot` 的 `evaluatePluginCompatibility()`：

- 只要声明了 `engines.dsh`，就**只按它判定**，`peerDependencies` 全部忽略；
- 判定方式是 `semver.satisfies(运行时版本, range, { includePrerelease: true })`；
- 不满足就拒绝安装，并把已经装进去的包回滚。

`0.2.1-rc.4`、`0.2.1-rc.5` 不在枚举里，所以判定为 false。而 DSH 的 rc 迭代节奏是几天一版：rc.3 是 10-23，rc.4 是 10-26，rc.5 是 10-29。**任何用精确枚举写预发布版本的插件，都会在新 rc 发布的当天失效。**

对比同一个插件的上一个版本：v0.3.0 写的是 `>=0.2.0-rc.2 <0.3.0`，rc.5 能通过。所以这不是「插件不支持新版」，而是「插件把范围从区间换成了枚举」。

## 三种解法

### 1. 等插件发版（最干净）

作者把范围放宽成区间即可，例如：

```json
"engines": { "dsh": ">=0.2.1-rc.2 <0.3.0-0" }
```

`<0.3.0-0` 这种写法会把 0.3.0 的所有预发布版本排除掉，比 `<0.3.0` 更严谨。实测 rc.5 通过。

### 2. 装旧版本

如果旧版本的声明更宽，可以指定旧版本安装。代价是拿不到新功能，而且旧版本可能有已修复的问题。

### 3. 按分支安装（上游把修复放在分支上时）

很多作者会把修复合在分支或 PR 上，但迟迟不发版。PlugBox 的插件市场支持按分支安装：点卡片左下角的版本号，选分支，装的是该分支当前的头提交。

这是旁路，不是正解：

- 分支是活口，上游继续推送就会变；
- 分支通常没经过作者的发布验收；
- 卸载重装才能拿到新提交。

## 给插件作者的三条建议

1. **用区间，不要枚举预发布版本。** `>=0.2.1-rc.2 <0.3.0-0` 一次写完整个 0.2.1 系列，不用每个 rc 都改。
2. **别把 `engines.dsh` 当成测试记录。** 它的语义是「我这个版本在哪些宿主上能跑」，不是「我只在这两个版本上测过」。后者应该写进 README 或 `docs/`。
3. **发版前用宿主自己的规则自测。** 一条命令就够：

```bash
node -e "console.log(require('semver').satisfies(process.argv[1], process.argv[2], { includePrerelease: true }))" 0.2.1-rc.5 ">=0.2.1-rc.2 <0.3.0-0"
```

## 附：怎么在安装前就看见这个问题

DSH 原生是在安装之后才校验。PlugBox 把索引里登记的兼容范围提前展示：与你当前版本不匹配的版本，卡片上直接标「版本不符」，安装按钮禁用，并在提示里写出它要求的范围。

索引方面，PlugBox 自己维护的索引会原样镜像每个插件在该提交上的 `engines.dsh`——不加工范围，也不把「未声明」写成「任意版本」。这样市场里的判断和宿主安装时的判断是同一套。
