Plugin Adapter & Manager

PlugBox：插件适配与管理工具

PlugBox 面向所有支持自定义插件的引擎层与智能体层工具：在一个面板里浏览、安装、更新、启用或停用插件，聚合多个插件索引源，把装不上的版本提前标出来；上游只把修复合在分支上时，可以直接按分支安装。它分两层——核心层定义与任何引擎无关的插件协议，适配层里每个宿主一个适配器负责翻译清单字段、安装方式、UI 注册与 RPC 方法。新增一个宿主只需加一个适配器，不改核心。

MIT 许可 核心层 / 适配层分层 DeepSeek Harness 已实测 macOS

它能做什么

插件管理与市场

读取宿主真实的插件服务，整包启停、逐行启停、安装、更新、卸载都落在当前 profile，不维护第二份数据。

宿主差异收敛在适配器

清单字段、安装方式、UI 注册协议、RPC 方法名、资源映射全部封在各自的适配器里，核心层保持中立。

多索引源聚合

把已订阅的索引合并成一个列表，按来源分组、按作者筛选，并显示每个索引源的条数与错误。

兼容性提前可见

按索引登记的兼容范围（在 DSH 上是 engines.dsh）判断：当前宿主装不上的版本标「版本不符」并禁用安装。

按分支安装

点卡片左下角的版本号，选仓库分支直接安装。适合上游把修复放在分支上、还没发版的场景。

安装

当前以 DeepSeek Harness 组合包的形式分发——dsh.bundle.patch 是 DSH 的协议字段，由 DSH 适配器提供。换到别的宿主后，安装参数由该宿主的适配器决定。

方式一：从插件索引安装（推荐）

  1. 打开 DeepSeek Harness 的「发现 → Index sources」，添加 https://raw.githubusercontent.com/Wcof/PlugBox/main/index.json
  2. 搜索 plugbox，点安装
  3. 重启 DSH 窗口（Host 端代码在启动时加载）

方式二：命令行

dsh plugin --profile web add github:Wcof/PlugBox

桌面端把 --profile web 换成实际的 profile 名（通常是 desktop）。

常见问题

PlugBox 支持哪些宿主？

第一个支持的宿主是 DeepSeek Harness（已实测 0.2.1-rc.5），zcode 的 DeepSeek Harness 是已知宿主但尚未实测。新增宿主 = 新增一个适配器 + 少量配置，核心层不用改。

插件显示「版本不符」是什么意思？

该版本的兼容范围（在 DSH 上是 engines.dsh）不包含你当前的宿主版本。宿主安装后会按 semver 校验并拒绝回滚；PlugBox 把这个判断提前到列表里。

按分支安装和普通安装有什么区别？

普通安装装固定提交；分支安装装分支当前的头提交，会随上游推送变化，适合还没发版的修复。

「PlugBox 收录」是宿主官方收录吗？

不是。它只表示收录在本项目的索引里；宿主官方收录按各宿主自己的标记判定（DSH 是 official）。

旧的 DeepSeekBox 订阅地址还能用吗？

不能。仓库已改名为 Wcof/PlugBox，旧地址已失效。请删除旧订阅，改用 https://raw.githubusercontent.com/Wcof/PlugBox/main/index.json。

English

PlugBox is a plugin adapter and management tool for engines and agent platforms that support custom plugins: install, update and enable plugins in one panel, aggregate multiple index sources, flag versions the running host cannot load, and install from a git branch when upstream has not published a release. It is split into a host-agnostic core layer and one adapter per host; DeepSeek Harness is the first supported host.
